# Security Policy

## Reporting a vulnerability

Please do not report exploitable vulnerabilities in public issues. Use GitHub's
private vulnerability reporting for this repository when it is available. If that
channel is unavailable, contact the repository owner privately through a verified
account channel and include only the information needed to reproduce and assess the
issue. Do not include real credentials, private user data, or production records.

If no private reporting channel is configured, repository maintainers must enable
one or publish a verified security contact before claiming a monitored disclosure
service. This file alone does not mean that private reporting is enabled.

## Scope and response

Reports should include the affected commit or version, impact, reproduction steps,
and any safe proof of concept. Maintainers will acknowledge reports when practical,
triage severity and affected versions, coordinate a fix and disclosure, and credit
the reporter only with their consent. Do not test against systems or data you do not
own or have permission to assess.

Security status and release readiness must be based on observed workflow results and
repository settings. A passing CodeQL or dependency scan does not certify the whole
system as secure.
